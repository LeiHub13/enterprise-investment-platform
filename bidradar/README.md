# 标讯雷达 BidRadar — 本地第一版

按主题搜索招标公告，查看搜索摘录、收藏、核实信息并跟进。有两条互相独立的数据通道：**DeepSeek Search & Fetch API**（宽覆盖，靠第三方索引）和**站点定向采集**（窄覆盖，直接读官方公告栏目页）。两者都不依赖模型记忆生成项目，线索永远带原始网址。

## Windows 启动

1. 将压缩包解压到 `D:\公司`，得到 `D:\公司\bidradar`。
2. 需要 Python 3.10 或更高版本。此版本服务端仅使用 Python 标准库，无需 pip、npm、Java 或数据库安装。界面使用 Vue 3 + Element Plus，依赖文件已内置在 `web/vendor`，**无需联网、无需构建**。
3. 将 `.env.example` 复制为 `.env`，填写：

   ```dotenv
   DEEPSEEK_API_KEY=你的DeepSeek密钥
   ```

   请保留真实文件名 `.env`，不要保存成 `.env.txt`。密钥仅在本地服务使用，不会传给网页。
4. 双击 `start.bat`。也可在 PowerShell 中执行：

   ```powershell
   cd D:\公司\bidradar
   py -3 app.py
   ```

5. 浏览器打开 **http://127.0.0.1:8765**。关闭运行窗口会停止服务和定时任务。
6. 在「关注主题」创建主题，然后「搜索项目」或「爬取项目」。未配置密钥时仍能使用主题、收藏、演示功能和站点采集（采集不需要 DeepSeek 密钥）。

若端口占用：`py -3 app.py --port 8766`，访问相应端口。修改 `.env` 后重启程序。

## 第一次使用

### 企查查招投标接口

开通企查查开放平台 ApiCode 958 后，在本目录已有 `.env` 中增加 `QCC_APP_KEY` 和 `QCC_SECRET_KEY`，重启 BidRadar；不要覆盖 DeepSeek 配置，也不要提交密钥。关注主题旁可手动发起查询，每次只请求一页、可能消耗一次接口额度，不会自动重试或加入定时工作流。符合主题规则且带原文网址的结果会去重并入库；企查查提供的预算、采购人和投标截止时间显示为待核实。平台内可使用省市名称筛选，独立页面支持关键词和信息类型。

- 创建主题，例如名称“OPC社区运营”，关键词 `OPC,一人公司,创业社区运营`，排除词 `OPC协议,工业通信`。
- 地区是加分项而非硬过滤：命中地区相关度 +10，未命中仍会保留，但卡片底部标注「地区待核实」。原因是搜索返回的正文常被截断，公告标题也常只写“盐城经开区”不写“江苏”，硬过滤会误杀本省公告。可填写 `江苏,南京,苏州,盐城`。
- 每个主题每轮最多发出 3 个查询。前两个查询用核心关键词，另一个查询按轮次选取单个地区或剩余关键词。明确关注创业或社区运营的 OPC 主题会补充「一人公司」「单人公司」。同一轮工作流里的相同查询复用搜索结果，各主题仍独立匹配。
- 开启“只搜索两个中央采购平台”会加入 `site:ccgp.gov.cn OR site:ggzy.gov.cn`，不包含所有地方平台。
- 匹配分数是规则分数，不是LLM语义判断或中标概率。关键词/地区/排除词可编辑。
- 打开项目详情可以查看来源、按需调用 Fetch 获取正文、人工填写预算、截止时间和跟进备注。
- 系统从可识别的官方正文中提取明确标注的投标或响应截止时间，并在详情保留对应原文片段。人工填写的截止时间优先显示。缺失或互相矛盾的时间显示「待核实」。
- 收藏与备注自动保存到 SQLite。CSV 导出可点击「导出 CSV」下拉选择：导出全部已收录公告，或只导出某个关注主题命中的线索（不受当前页面筛选影响）；文件名带主题名和日期，倒数第三列「来源渠道」标明该条来自 DeepSeek 搜索还是站点采集，倒数第二列「形态」标明该条是「疑似公告」还是「疑似非公告」，末尾「命中主题」列标明每条线索归属哪些主题。
- 线索列表默认优先展示截止时间未到的招采机会。可按招采机会、更正、中标或成交、采购意向、终止、合同等类型和截止状态筛选。也可切换到最近收录、公告日期或规则相关度排序。
- 搜索会把门户首页、栏目列表页、聚合导航页、广告位和新闻资讯一起返回。入库时按标题形态打 `is_notice` 标记（1=疑似公告，0=疑似非公告），列表默认隐藏后者，可在列表头勾选「显示疑似非公告」查看，卡片上带灰色「疑似非公告」标签。规则命中门户名（如「常州市政府采购网」）、`_` 拼接的聚合导航（如「江苏省教育招投标_…_招标网」）、「第 N 页」、「黄金会员/即将跳转/已为您找到」、媒体域名（今日头条、中国江苏网等）。这批规则在 57 条人工标注样本上命中噪音 21 条、误杀 0 条；判错的条目不会被删除，改规则后可用 `core.reclassify()` 重算。

## 采购意向与关注采购人

- 「采购意向」集中查看已收录的意向线索。配置 DeepSeek 密钥后，可按主题搜索中国政府采购网意向原文；页面也提供官方查询入口。打开原文可以核对拟采购内容和时间，收藏后可在「收藏与跟进」继续处理。正式招采安排以随后发布的采购公告为准。
- 「关注采购人」可以按机构名称添加关注，也可以在公告详情中关联采购人。页面汇总已收录并关联到该机构的公告和意向。取消关注会保留原有公告关联。
- 采购人信息可以手动核实和更正。定时工作流按参与主题获取线索，关注名单用于汇总其中已关联的采购人。

## 定向采集（爬虫通道）

主题卡片上的「爬取项目」走的是这条通道，调 `POST /api/crawl`。它**不经过 DeepSeek**，不消耗搜索额度，未配置密钥也能用。

为什么要有第二条通道：搜索接口每个查询最多 50 条且不能翻页，索引里省市交易中心的数据稀疏（搜 OPC 只有几十条正是这个原因）。招标公告是法定集中发布的，源有限、可枚举，所以直接读官方栏目页能补上搜索够不着的那部分，并且拿到的发布日期是站点给的权威值。

当前接入以下来源（`crawler.py` 里的 `SOURCES`）：

| 源 | 列表页 | 模式 | 每轮约 | 详情正文 |
| --- | --- | --- | --- | --- |
| 江苏政府采购网 | 首页采购公告栏目 | 按 URL 正则挑链接 | 7 条 | 无（正文由前端脚本填充） |
| 无锡市公共资源交易中心 | 采购公告栏目（脚本渲染） | 官方列表 JSON 接口 | 20 条 | 有 |
| 徐州政府采购网 | 首页采购意向公开 | 从列表读取标题、采购单位与日期 | 以当前列表为准 | 提供原文链接 |

工作方式：

- 每个源抓 1 个栏目页，解析出「标题 + 链接 + 日期」，标题里没有公告类词的条目直接丢掉。栏目页由脚本渲染、静态 HTML 没有列表时（如无锡采购公告），改调该页自己使用的官方 JSON 列表接口。
- 每个源每轮最多请求 6 个详情页，优先检查新公告或标题有变化的公告，同等条件下优先检查标题命中关键词的条目。24 小时内的详情缓存可复用，过期详情可在刷新前参与匹配。
- 抓到的东西仍然要过和搜索完全相同的 `evaluate()` 规则与 `is_notice()` 形态判定，判定口径不会因为换了通道而变松。
- 请求之间固定停顿 1 秒，带明确 UA，只读公开列表页和详情页；不绕验证码、不碰需要登录的页面。触到验证码或风控就如实报错，不做绕过。
- 单个源失败只影响该源。工作流记录分别显示每个来源的列表条数、详情请求、缓存复用和错误。

加一个源只需在 `SOURCES` 里加一条：`mode` 用 `ewb`（新点模板，日期在 `span.ewb-date` 里）或 `link`（按 `url_re` 匹配链接）；站点正文由前端脚本渲染时设 `'detail': False`，省掉无用的详情请求。若整个栏目页都由脚本加载，可仿照无锡源配置 `wuxi_api`，直接调用站点自己的 JSON 列表接口。

局限：栏目页改版会让正则失效；部分站点的详情正文拿不到，只能用标题参与匹配，命中率会低一些。采集到但未命中当前主题的公告不会入库——这是有意的，避免把无关公告堆进项目库。

线索来源在「发现项目」页的「全部来源」下拉里筛选：全部来源 / DeepSeek 搜索 / 站点采集 / 演示快照。卡片和详情弹窗上都有对应标签，统计卡会显示「搜索 X · 采集 Y」。同一条公告如果两条通道都碰到，保留首次入库时的来源标记，不会因为后一轮换了通道而漂移。

## DeepSeek 接口

- Search: `POST https://api.deepseek.com/v1/tools/search`
- 请求：`query`（不超过128字符）、`count: 50`、`need_content: true`。
- Fetch: `POST https://api.deepseek.com/v1/tools/fetch`，请求包含 `url`。
- 认证：`Authorization: Bearer <DEEPSEEK_API_KEY>`。
- 官方说明：https://api-docs.deepseek.com/guides/search/
- 调用产生的费用由你的账户承担。没有密钥不会发起搜索；无效密钥、余额不足、限流、网络异常均显示错误。
- 此交付环境没有你的真实密钥，已用模拟响应验证接口适配，但未完成真实账户端到端检索测试。

## 数据与定时任务

- 数据存放：`data/bidradar.db`，程序首次启动自动创建。
- 升级代码后重启即可：程序启动时会自动补齐新增的表和列（例如采购人表），已有数据不会被清空。
- 备份：退出程序后复制整个 `data` 目录。恢复时同样先停止程序。
- 演示数据需手动加载，来源是2026-11-02整理的历史公告快照，不代表当前状态，不会自动冒充实时搜索结果。
- 同一网址保留更完整的正文、优先采用官源日期，并保留收藏、备注和人工核验字段。首次收录时间和最近发现时间分别记录。不同网址继续分别收录。
- 「自动工作流」可按每天固定时间或每隔 N 小时执行，支持 DeepSeek 搜索、站点采集或两条通道一起运行。每轮采集同一栏目一次，供所有参与主题匹配。已有工作流默认继续使用搜索，编辑工作流即可启用采集。单独使用采集无需 DeepSeek 密钥。程序运行时调度生效。
- 新建工作流时把「上次执行」记为当时，因此不会因为今天的时点已过而立刻补跑一整轮；想立刻看效果请点「立即运行」。
- 每轮工作流会记录参与主题数、命中数、**新增数**（同一网址重复出现只算一次）以及每个主题的明细，可在「自动工作流」页展开查看，并按轮次单独导出新增线索。勾选「跑完自动导出」时同时写入 `data/exports/workflow-run-<轮次>.csv`。
- 本版本没有邮件/微信/桌面通知；搜索记录和工作流的运行记录用于查看更新。
- 失败不会清空旧项目，部分请求失败显示“部分成功”；再次搜索可能消耗API额度。
- 同一时刻仅允许一个主题搜索或一轮工作流。运行中请勿修改主题或工作流配置。
- 界面最多显示最近2000条公告、50条搜索记录、30轮工作流记录；数据库保留全部数据。全量导出不受 2000 条限制。

## 项目结构

```text
bidradar/
  app.py          本地HTTP服务、API、定时任务、静态资源路由
  core.py         DeepSeek适配、主题规则、SQLite、导出、采集入库
  crawler.py      站点定向采集：列表页/官方接口解析、详情正文提取、逐源容错
  web/
    index.html    页面外壳（Vue 3 + Element Plus，无需构建）
    app.js        前端应用逻辑与 Element Plus 模板
    style.css     Element Plus 之上的定制样式
    vendor/       本地化的 vue / element-plus / icons（离线可用）
  tests/          自动测试
  demo.json       可选历史演示快照
  .env.example    密钥配置模板
  start.bat       Windows启动入口
  start.ps1       PowerShell启动入口
```

## 版本范围

这是方便本机直接启动的单用户MVP，采用标准库HTTP服务＋SQLite＋Vue 3/Element Plus 前端。前端为免构建的单页应用（运行时模板编译），依赖全部本地化在 `web/vendor`，不依赖 CDN。当前未采用 Spring Boot；后续可以保留数据模型和业务流程迁移。只监听127.0.0.1，并校验Host/Origin，不要把此开发服务改为公网监听。

已完成：主题管理、DeepSeek 搜索与正文获取、江苏政采及无锡交易中心公告采集、徐州政府采购意向采集、采购人关注、原文证据保留、网址去重、公告类型和截止状态筛选、收藏跟进、SQLite、CSV，以及搜索和采集的定时工作流。

后续范围包括新增站点和栏目翻页、跨网址项目归并、预算和资质提取、附件解析、账号权限、云端定时任务和外部通知。参与条件和更正后的截止时间以采购方最新公告为准。

不要将 `.env` 或 `data/` 提交到公开代码仓库。
