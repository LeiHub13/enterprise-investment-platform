# 招商 Agent 重构：现状与实施计划

检查日期：2026-11-09。范围是现有平台中的招商 Agent；泛悦城市广场是首个招商楼宇，不再建设单独的泛悦 Agent 产品。

## 现有工程

| 位置 | 已有能力 | 需要补齐或修正 |
| --- | --- | --- |
| `frontend/` | Vue 3、TypeScript、Vue Router、Element Plus；已有企业、项目、线索、跟进、Agent 流式界面 | 隐藏独立泛悦 Agent 入口；展示来源、时效、三类评分与审批结果。当前没有 Pinia、Axios、ECharts，不为形式上的技术栈替换现有正常工作的功能。 |
| `backend/` | Spring Boot 3.3.5、JDK 17、Spring Security、MyBatis、MySQL；RBAC、数据范围、企业/项目/线索/跟进及 Agent 代理 | 设置密钥后支持 JWT 并兼容原随机令牌；MyBatis 不是 MyBatis-Plus。需继续补齐业务接口及生产部署。 |
| `agent/` | FastAPI、Deep Agents、LangGraph、PostgreSQL/SQLite checkpoint、三分规则评分、人工中断与恢复；业务数据经 Java API 访问 | 已支持最近四轮上下文与两个专业分析器；需完善真实企业核验、跨平台关联和数据源联调。 |

业务对象映射以现有表为基础：`sys_user`、`ent_enterprise`、`collector_record` / `data_source_record`、`ent_company_signal`、`crm_project`、`crm_lead`、`crm_lead_evidence`、`crm_followup`、`agent_run`、`agent_tool_log`。现有 `agent_run.id` 和会话 ID 为字符串，符合当前 API，不能直接声称已满足所有主键 BIGINT 的新设计；增量迁移必须明确兼容与历史数据方案。

## 技术核对

- 本机 Python 3.13.0、uv 0.13.5、Node.js 24.21.0、Maven 3.9.9、JDK 17.0.13。全局环境已有 LangGraph 1.2.11、`langgraph-checkpoint-sqlite` 3.1.3、`langchain-openai` 1.4.3。项目隔离环境已安装并检查 Deep Agents 0.7.34、LangGraph 1.2.20、PostgreSQL checkpoint 3.2.0 的实际调用签名；项目依赖文件已固定版本并完成模拟模型工作流测试。
- 官方 Deep Agents 文档使用 `create_deep_agent(..., tools=..., subagents=..., checkpointer=...)`；Subagent 字典包含 `name`、`description`、`system_prompt`、`tools`。人审可使用 LangGraph interrupt，同一 thread 恢复；生产 checkpoint 使用 PostgreSQL 并在首次使用时执行 setup。
- 企查查 718 文档提供 `GET /Recruitment/GetList`，按企业名称或统一社会信用代码查询，`pageSize` 最大 50；需要开放平台密钥、企业实名和场景审核。该接口是对候选企业的补充，不是全市企业发现接口。2001 企业信息核验须另行授权，正式查询可能计费。
- 58 合作接口的实际能力、认证、字段、分页与通知格式尚无授权文档；不得猜测或实现所谓真实接口。
- 初始检查时根 Compose 含 MySQL、Redis、RabbitMQ、MinIO，没有 PostgreSQL 或完整应用服务；旧泛悦骨架的容器当时正在运行。后续已扩充 Compose，并停止旧独立项目的业务与 Agent 服务，保留数据库和数据卷。
- 基线检查：前端生产构建通过；后端测试 34 项、0 失败、1 项手动联网检查跳过。后端测试需允许本机回环连接，在沙箱内运行会被网络权限拦截。

参考官方文档：[Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview)、[Subagents](https://docs.langchain.com/oss/python/deepagents/subagents)、[人工审核](https://docs.langchain.com/oss/python/deepagents/human-in-the-loop)、[PostgreSQL checkpoint](https://docs.langchain.com/oss/python/langgraph/add-memory)、[企查查招聘 718](https://openapi.qcc.com/dataApi/718)、[企查查核验 2001](https://openapi.qcc.com/dataApi/2001)、[58 开放平台](https://open.58.com/)。

## 目标架构

```text
招商工作台 ──用户权限──> Spring Boot（唯一业务数据入口、审核、审计）
                              ↕ 用户授权的内部 API
                      招商 Supervisor（Deep Agents）
                       ├─ 招聘分析 Subagent
                       ├─ 求租分析 Subagent
                       └─ 核验 / 实体关联 / 确定性评分
                              ↕
                   LangGraph + PostgreSQL checkpoint

独立采集器：企业候选池 → 企查查招聘 / 58 mock → 清洗去重 → Java 入库 → 事件
```

采集器和 Agent 不直接连接 MySQL。模型不得直接给出任意数值评分；招聘活动只作为间接信号。来源、发布时间、采集时间、是否演示和过期状态均须保留。没有授权依据时，工商主体状态为待核验，不能仅凭相似名称合并主体。人审前不得写线索；批准后只能创建待审核线索，后续审核与跟进需相应权限。

## 分阶段实施及验收

1. **现状、兼容性与计划**：完成代码、环境及官方接口检查，建立本文件与基线。
2. **基础设施和迁移**：在根 Compose 增加 PostgreSQL 与所需应用编排；编写可追踪、可回退/重入的增量迁移，保留现有数据，配置泛悦城市广场目标面积 100～300㎡，未知地址和租金保持空值。先检查服务端口及数据卷再启动，验证数据库与消息服务连接。
3. **Java 业务闭环**：复用企业、项目、权限与 CRM，增补楼宇、待审核线索、证据、审核、任务、监测、审计和 Agent API；逐项验证权限、跨用户隔离、事务及幂等。JWT 与已有令牌的兼容迁移单独验证，不强制所有人同时退出。
4. **采集**：将企查查按官方文档实现候选池查询及分页；创建 58 接口抽象和显式 mock；归一化、去重、有效期、增量游标、事件、重试和监控。mock 不混入真实结果。
5. **Agent**：隔离环境锁定并测试 Deep Agents；按需调用专业 Subagents，使用 LangGraph 状态、checkpoint、人工中断恢复；使用独立规则引擎输出意向、匹配、可信度及按 0.45/0.40/0.15 加权的优先级，保留原因和未知项。
6. **前端**：统一为招商 Agent 入口；复用工作台、企业与线索页，补充数据来源、求租有效期、三分、报告、运行轨迹和审核交互，演示数据明确标记。
7. **联调与部署**：分别运行 Python、Java、前端及迁移测试，启动 Compose，验证登录→候选分析→报告→人工确认→待审核线索→审核→跟进→追溯的完整链路；无第三方凭证时只验证明确标注的 mock 流程。

每阶段更新本计划、README 和实际测试结果；无法验证的部分不得标记为完成。

- 阶段 1：检查与计划完成。
- 阶段 2～7：进行中。统一入口、PostgreSQL checkpoint、默认楼宇目标、三分评分、Deep Agents 两个专业 Subagent、人工确认后创建带证据的待审核线索、线索审核及前端展示已实现。新增迁移在隔离 MySQL 上验证重复执行；PostgreSQL 中断重连恢复和 MySQL 审核幂等已通过集成测试。
- 根 Compose 已增加应用服务构建及依赖健康检查；三个应用镜像均已构建，临时独立栈通过 API 完整流程测试。原独立泛悦 Agent 及其健康检查服务已停止，旧数据库和数据卷保留。
- 企查查按已知企业的招聘查询、页数限制、签名和模拟响应已测试；58 演示连接器支持显式预览与手动上传，尚未接入自动采集。真实招聘响应封装仍需凭证联调。
- 采集记录、信号和事件在 Java 同一事务落库；独立发布器使用租约、持久队列和 RabbitMQ 发布确认。可选消费者使用授权用户令牌，按事件 ID 幂等启动 Agent，并将暂时失败或持续失败分别放入重试队列和待处理队列；演示、过期及历史版本不自动触发。人工确认之前不会创建线索。
- 已增加按来源标识的版本游标：区分新增、更新、不变与较早版本，保留历史快照；有来源更新时间时防止乱序覆盖，演示与非演示记录互相隔离。到期求租记录在查询和评分时即时视为失效，显式失效扫描可持久化状态并发布失效事件。此游标用于单条来源记录版本，不等同于平台分页/全量同步游标。
- 已增加按企业的企查查招聘监测任务、独立工作进程及页面配置。新任务默认暂停，正式模式需授权和凭证；任务使用租约防止并发重复领取，连续失败三次自动暂停。运行记录和上次完成时间可查看；58 正式监测仍待合作授权。
- 已按 2001 公开文档实现企业主体核验：只保存身份和登记状态字段、记录来源及 30 天有效期，演示结果不能覆盖真实结果；核验异常或档案异常时暂停建线索。正式监测仅在显式配置 `QCC_VERIFY_ON_MONITOR=true` 时额外查询；尚未取得真实接口授权，需使用正式凭证联调。
- 同一用户同一会话最多带入最近四轮已生成报告作为上下文，每次运行仍有独立 checkpoint thread；历史读取按用户隔离。
